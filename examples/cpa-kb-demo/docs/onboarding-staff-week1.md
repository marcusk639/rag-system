# New Staff Onboarding — Week 1

> **SYNTHETIC SAMPLE.** Fabricated for demo purposes.

**Document type:** SOP
**Owner:** Sarah (senior, mentor lead)
**Last reviewed:** 2026-04-30

## Purpose

The first week for a new staff accountant. Each day has a primary objective; the goal by Friday is for the new hire to be self-sufficient on the time-coding system, able to navigate Karbon, and know who to ask for what.

This SOP is intentionally short. The mentor (currently Sarah) fills in the rest based on the hire's background and the firm's active workload.

## Day 1 — Setup and orientation

**Morning (with HR):**

- Payroll setup, benefits enrollment, NDA, IT acceptable-use policy
- Karbon, SharePoint, QBO, Teams, Outlook accounts provisioned
- Two-factor enrolled on every system

**Afternoon (with mentor):**

- Walk through the firm's org chart — who does what
- Walk through the Karbon UI: work items, time entries, client requests
- Read [Time Coding Guide] end-to-end. ASK questions while reading; don't save them up.
- Log your first time entry (training to the `TRAINING` code, see [Time Coding Guide])

## Day 2 — Karbon-shadowing

- Mentor opens 3 of their active work items and walks through them
- Hire opens [Karbon Template Catalog] and reads it
- Pick one engagement type the hire will work on this week; mentor demos one from start to finish
- End of day: hire writes a 1-paragraph summary of what they understood + 3 questions to ask tomorrow

## Day 3 — First supervised task

- Mentor assigns one well-bounded task on an active engagement
  - Examples: input data from a 1099 batch, reconcile one bank account, prepare a W-2 summary
- Hire does it; mentor reviews EVERY step before time is logged
- After: hire writes up "what I would do differently next time" in their personal-notes file

## Day 4 — Second supervised task

- Same pattern, different engagement type if possible
- Hire is encouraged to **ask the KB bot first** before asking the mentor — this builds the habit
- If the KB doesn't have the answer, ask the mentor and the question gets logged in the weekly KB-gaps digest

## Day 5 — Review + Friday process

- Review the week's time entries together — were codes right? descriptions adequate?
- Walk through the Friday workflow: time-entry approval, week-end status, weekend coverage
- Introduce to the partner (5-min office visit; no agenda required)
- Mentor gives explicit feedback: what's working, what to focus on next week

## Resources every new hire should bookmark in week 1

- [Time Coding Guide] — read first, refer to weekly
- [1040 Intake Checklist] — even if not doing 1040s yet, understand the structure
- [Karbon Template Catalog]
- This document — to track their own progress

## Week 2 onward

After Week 1, mentor and hire move to a weekly 30-min sync; daily check-ins drop. By Week 4, hire is logging time independently. By Week 8, hire has handled at least one engagement type end-to-end with supervision.

## Common Week-1 friction (and how to handle)

- **"I don't want to ask Chris a dumb question."** Direct the hire to the KB bot. If the KB doesn't have the answer, the question is in fact NOT dumb — it's a KB gap and gets logged. This is per [KB Bot adoption playbook] (Marcus's project document).
- **"I don't know what code to use."** [Time Coding Guide] has the catalog; the FAQ at the bottom covers the most common cases. If still stuck, code to `TRAINING` and clean up at Friday review.
- **"This is overwhelming."** It is. The firm has a lot of moving pieces. Mentor reassures: ramp is 3-6 months to "comfortable," 12 months to "competent." Week 1 is not a competence test.
