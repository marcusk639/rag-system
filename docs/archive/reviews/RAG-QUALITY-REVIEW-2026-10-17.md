# RAG Quality Review — 2026-10-17

**Status:** Current · **Scope:** ingestion → chunking → embeddings → retrieval → prompting → answers, plus the MCP surface · **Method:** code reading, a chunker reproduction script, and SQL probes against local Postgres. Findings marked _unverified_ were not reproduced.

## Verdict

The system is well engineered where it matters most for a firm knowledge base:

- **Access control is enforced inside the retrieval SQL**, before the candidate pool is cut. That prevents both leaks and silently short result lists.
- **Hybrid retrieval is correct.** The sparse arm ORs keywords so it doesn't silently become dense-only, quotes each keyword so pasted text can't inject query operators, and RRF combines the two arms by rank.
- **Embeddings are configured correctly.** Gemini uses separate document and query task types and normalizes to unit length. Local BGE adds its query prefix.
- **The prompt treats retrieved text as untrusted.** It escapes it, groups chunks by document in reading order, and returns a fixed answer when nothing is retrieved.

The weak points are in four places:

- **Ingestion correctness.** Heading paths were wrong, and a failed re-embed left stale chunks in service.
- **The relevance floor.** It could not do its job as designed, and it is off in production.
- **Answer-time verification.** Invalid citation numbers stay in the answer text.
- **Unused signals.** Page numbers and title/heading weighting are never used.

Seven fixes are applied in this change. Everything else is ranked below with an effort estimate.

Live production config (read-only check): `EMBEDDING_PROVIDER=gemini` (`gemini-embedding-001`, 768d), `GENERATION_PROVIDER=gemini` with `GENERATION_MODEL=gemini-flash-latest`, `RERANK_PROVIDER` unset (none), `RETRIEVAL_MIN_DENSE_SIMILARITY` unset (floor off).

## 1. Fixes applied in this change

All of these were written test-first. Every workspace unit suite passes, and build, typecheck and lint are clean. `pnpm eval` is unchanged from the baseline on both question sets (recall@1 91.2% / 92.5%, MRR 1.000 / 0.975). The harness uses a fake bag-of-words embedder, so this rules out a regression but cannot show the heading-path gain; `pnpm eval:real` would.

**Rollout notes**

- **F1 reaches existing documents only when they are re-ingested.** The content hash covers only the markdown and `CONTENT_PROCESSING_VERSION`, not the chunker output. To apply the fix to the whole corpus, bump `CONTENT_PROCESSING_VERSION` (this re-embeds everything on the next sync) or run a full sync. See R4.
- **F4 changes nothing until the floor is turned on.** Next step: set `RETRIEVAL_MIN_DENSE_SIMILARITY` from the audit log's `top_score` distribution. For `gemini-embedding-001`, plausible on-topic floors are 0.55–0.65, but measure before choosing. With F4 in place, the floor becomes the main defence against confident answers to off-corpus questions.

### Low

- **Large code blocks are split at sentence punctuation**, so `foo.bar()` gets cut and only the first piece keeps its fence. Split on newlines and re-fence each piece instead.
- **The table chunker can go over budget when rows overlap** (`rowOverlap: 2` with wide rows). Re-check the carried rows against the budget.
- **Overlap is cut at a token boundary**, so a chunk can start mid-word or with U+FFFD. Advance to the next whitespace.
- **Claim verification only checks that the quote exists.** It has no minimum quote length, so "the" passes. Require at least about 20 characters and 3 tokens (this affects eval only).
- **The claim-extractor prompt doesn't fence the document**, and `metaByClaim` collides when two claims have identical text (eval only).
- **No prompt caching on Claude.** The roughly 1.4k-token system prompt may be below the cache minimum, so verify `cache_read_input_tokens` before relying on it.
- **The prompt has no current date**, so "this year's deadline" can't be judged against the `modified=` dates. Add `Today's date:` to the user message, not the system prompt, to keep the system prompt cacheable.
- **The condenser doesn't escape `</conversation>`.** Impact is limited to the caller's own scope.
- **The HNSW index is bypassed by the `EXISTS` pre-filter**, which is correct and fast at today's corpus size. Use `hnsw.iterative_scan` (pgvector ≥ 0.8) once the corpus outgrows a sequential scan. Confirm the pgvector version in the `postgres-ssl` image first.
- **Duplicate collapse is exact-match only.** Copies that differ slightly survive. A cheap MinHash or Jaccard check on token shingles would catch near-duplicates.

## 3. Enhancements that would make the system more useful

Ordered by value per unit of effort.

1. **E1: Embed context, display the body.** Embed `title › heading path` plus the body without the overlap, and keep the overlap only in the displayed text. This fixes R1, keeps duplicated overlap out of the keyword index, and usually improves dense retrieval for short sections whose meaning depends on their heading.
2. **E2: Weighted tsvector.** Use `setweight(title ‖ heading_path, 'A') ‖ setweight(body, 'D')` in the `chunks_tsv` trigger, as a forward-only migration. Questions that name an SOP or section then rank that section first. This is the cheapest meaningful improvement to keyword ranking.
3. **E3: Enable and tune the relevance floor**, now that F4 makes it sound. Combine it with an abstention metric: classify each answer as A (fully covered), B (partly covered) or C (refused) by matching `EMPTY_ANSWER` and the `Not covered by the documents:` line, and store that in `audit_log`. Over-refusal and over-answering then become measurable from production traffic.
4. **E4: Reuse embeddings of unchanged chunks on edit.** `chunks_hash_idx` exists but nothing uses it. When a document changes, copy the vectors of chunks whose `(hash, provider, model)` already exist, and embed only the new ones. Small edits to large SOPs would then cost almost nothing, and the F2 failure window shrinks.
5. **E5: Page-aware citations.** `chunks.page` exists but is NULL for every chunk; a local check found 0 of 7 populated, and no chunker sets it. Carry page markers from the parser (Unstructured `page_number`, PDF page breaks), set `Chunk.page`, and render "p. 4" in citations. For PDFs this matters as much as the document title.
6. **E6: Verify procedure steps when answering.** Run the existing `verifyClaim` against the cited document's chunks for numbered steps in procedure answers, and flag any step that can't be found. This targets the main risk the prompt warns about: paraphrasing a procedure wrongly.
7. **E7: Native Claude citations** (if generation moves to Claude). Send each context document as a `document` block with `citations.enabled`. The API returns character spans of the cited text, so citations are checked by the API rather than by a regex, which fits the audit-trail requirement.
8. **E8: Conflict surfacing.** When the answer says sources disagree, return the conflicting citation pairs with their `modifiedAt` dates, so web and Teams can show a "sources conflict" badge instead of hiding it in prose.
9. **E9: A reranker within data-residency rules.** Hosted rerankers count as egress, and `client-data` mode blocks them. A local cross-encoder (`bge-reranker-base` via the same Transformers.js runtime as the local embedder) would make reranking available in every compliance mode. Benchmark it with `pnpm eval:gold` before turning it on.
10. **E10: Recency and freshness signals.** Documents carry `sourceModifiedAt`, but ranking ignores it. A small tie-break, or an opt-in time-decay filter (`modified_after`), helps with questions about the current year where several versions of an SOP exist.

## 4. What I checked and found sound

- **Access control** is enforced inside both candidate CTEs and again in the final SELECT. An empty scope returns before the query reaches the database.
- **The sparse query** uses OR semantics with `quote_literal`, and a query made entirely of stop words degrades safely. An all-stop-word query hits no keyword matches and is answered by dense retrieval alone.
- **Dense search** is restricted to the active provider and model. `ef_search` tracks the pool size, and non-finite query vectors are rejected.
- **Gemini embeddings** use the `RETRIEVAL_DOCUMENT`/`RETRIEVAL_QUERY` task types and are L2-normalized at 768d. All-zero vectors are rejected and returned counts are checked.
- **`replaceChunks` is atomic per document.**
- **The prompt** treats sources as untrusted, escapes them, groups chunks by document in reading order, puts the question last, and has an explicit A/B/C coverage rule and a policy for conflicting sources.
- **The empty-retrieval short-circuit** answers without calling the model. Neighbour expansion is capped by `MAX_ASK_TOP_K`, and per-chunk TRI screening runs before generation.
- **Streaming** reports mid-stream errors as SSE `error` events.
