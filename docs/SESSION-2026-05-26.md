## What's NOT built yet (pick up here)

### v0 — TS table-aware chunker (DONE, 2026-05-26)

Status: shipped in this session as `packages/rag/src/chunking/table-chunker.ts` + `composite-chunker.ts`.

**Implementation**:

- `TableChunker.chunk({ table, startOrdinal })` consumes a single `ParsedTable`. Returns `null` for `narrative`/`freeform` sheets or tables without structured `headers`/`rows`, signalling the caller to fall back to MarkdownChunker.
- For `tabular` sheets: row-grouping with the header line repeated at the top of every chunk, row-based overlap (default 2 rows), and an oversized-row fallback that emits one-row-per-chunk rather than dropping data.
- For `financial_model` sheets: tries whole-sheet first; falls back to row-grouping if it exceeds chunkSize.
- `CompositeChunker` is the new entrypoint wired into the worker (`apps/worker/src/deps.ts`). It detects a spreadsheet doc by `tables.some(t => t.sheetType !== undefined)` and routes the entire doc through `TableChunker`; narrative/freeform sheets get re-routed back through `MarkdownChunker` per-table. Non-spreadsheet docs stay on `MarkdownChunker` as before.
- Ordinals are assigned globally across the document so retrieval still has a stable position sequence.

**Tests**: 17 vitest specs covering header repetition, no-mid-row-split invariant, oversized rows, financial_model whole-sheet vs. fallback, narrative pass-through, ordinal continuity across multiple tables, deterministic hashes, row overlap, pipe escaping.

**Decisions worth flagging** (revisit if retrieval quality data suggests):

- Spreadsheet docs skip MarkdownChunker entirely (parsed.markdown IS the rendered tables, so layering both = duplicate chunks). For non-spreadsheet docs with embedded tables (PDFs/DOCX), tables stay inline in the markdown — surfacing them separately is a v1 concern.
- 2-row overlap default. Trades a small amount of duplication for cross-chunk reference continuity (e.g. totals row mentioned in chunk N + 1 still visible at the top).

Reference: Chonkie's `TableChunker` (Python source linked in `docs/SESSION-2026-05-26-research.md`).

## Key non-obvious decisions made this session

These are documented in code comments at the relevant sites, but listed here for fast orientation:

| Decision                                                        | Where                                                     | Why                                                                                                                                                                                                                        |
| --------------------------------------------------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Reciprocal Rank Fusion (k=60) for hybrid retrieval              | `packages/db/src/queries.ts:hybridSearch`                 | Scale-invariant fusion of cosine vs `ts_rank_cd`. Literature-standard.                                                                                                                                                     |
| `SET LOCAL hnsw.ef_search` per query, wrapped in tx             | same                                                      | Tunable recall vs latency without index rebuild. Default 100 (Postgres default 40 is too low for RAG).                                                                                                                     |
| Filters applied at outer SELECT, not inside dense/sparse CTEs   | same                                                      | HNSW can only accelerate `ORDER BY <=> LIMIT N` over the full table. JOIN-in-CTE was a CRITICAL finding from cycle 1.                                                                                                      |
| Constant-time bearer auth via SHA-256 + `timingSafeEqual`       | `apps/api/src/auth.ts`, `apps/mcp/src/transports/http.ts` | Replaces `Set.has` (not constant-time). Iterates all candidates even after match.                                                                                                                                          |
| Markdown-aware chunker prepends `# {headingPath}` to each chunk | `packages/rag/src/chunking/markdown-chunker.ts`           | Vector retrieval scores chunks in isolation — heading path recovers the structural context the vector lost.                                                                                                                |
| Content-hash short-circuit in pipeline                          | `packages/ingestion/src/pipeline.ts:ingestOne`            | Re-ingesting an unchanged source document is a no-op for embedding/chunking. Cuts re-sync cost massively.                                                                                                                  |
| `meta/_journal.json` with `entries: []`                         | `packages/db/drizzle/meta/_journal.json`                  | Drizzle migrator throws if file missing. `0000_init.sql` is hand-authored (has `DO $$` blocks the breakpoint parser can't split) — Phase 1 applies it directly; Drizzle migrator handles future generated migrations only. |
| pydantic camelCase aliases on wire                              | `services/parser-py/app/main.py:_CamelModel`              | Wire format is consumed by TS — match the consumer's naming, keep Python idiom internally.                                                                                                                                 |
