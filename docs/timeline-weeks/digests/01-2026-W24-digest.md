# Week 2 (W24): Jun 08 - Jun 14, 2026 — The Surge

> The week the proposal became code: five phases, four PRs, and a Python parser promoted to constitutional law.

## The story

Week 1 ended with a paper architecture and a handoff to a future self. Week 2 cashed it. Across 25 sessions and 305 observations, Claude executed the five-systems unification plan it had written days earlier — the rare case of an AI following through on its own prescription rather than relighting the same fire. The build opens at 1:48 a.m. on Jun 8 and does not really stop.

**The @rag/services extraction — the drift's cure.** The first hour does the thing Week 1 only named. A new `@rag/services` package appears (obs 529), a transport-agnostic `ServiceDeps` interface is defined (530), and the five canonical functions — `searchDocuments`, `askQuestion`, `getDocumentById`, `triggerSync`, `listPublicSources` — land in quick succession (532–536). Then the MCP tools and HTTP routes are rewired to _import_ that logic instead of reimplementing it (538–544, 763, 768, 775). The HTTP↔MCP behavioral drift that motivated the whole effort is not patched — it is structurally deleted. Routes become "thin validation-and-delegation adapters" (768).

**The @rag/runtime composition root.** Phase 2 hoists dependency construction into `buildCoreDeps` (546–554): the DB pool, embedder, retriever, queue, optional generator, and a hardened idempotent `close()`, built once and consumed by all three apps. "No inline core construction, all apps use buildCoreDeps" (553). Phase 3 then hunts duplication: `filterSchema`, the bearer-token verifier, and source sanitization (`sanitizeSource` → shared `toPublicSource`) collapse to single owners in `@rag/core` and `@rag/db` (555–569), with new tests for the extracted `createTokenVerifier`.

**The worker's single-writer fix.** The C2a bug — duplicate writes to `ingestion_jobs` — gets resolved by making `triggerSync` the sole writer and having the worker merely _update_ producer-created rows (522–528, 593, 764). A new `SyncAlreadyRunningError` replaces a generic throw. This proves fragile under test: the C2a regression later throws uncaught (718), and `triggerSync`'s error handling is found to mask the original failure if the cleanup delete throws (771) — hardened in a dedicated follow-up session (778–781).

**The connector unification.** Jun 9 is a single sustained sweep: cursor codec and a shared `paginate()` utility extracted across all four connectors — Outlook, SharePoint, Google Drive, Gmail — with `runInitial`/`runDelta` collapsed into single-page fetchers (612–630, 722). Typecheck and existing tests stay green throughout.

**The parser as source of truth.** Phase 4 wires an OpenAPI type-generation script so `ParsedTable`/`ParsedDocument` flow from the Python parser's Pydantic models into TypeScript (704–716). Code review immediately flags the seam: Pydantic's `metadata` field lacks `additionalProperties`, so the generated type degrades to `Record<string, unknown>` with no boundary validation (714, 715, 774) — the Week 1 "wire-contract fragility" thread, now named precisely.

By 9:38 a.m. Jun 10, obs 726 declares the refactor **COMPLETE — all six phases verified and committed**, pushed as PR #3. The remainder of the week is consolidation: a tense merge-conflict reconciliation on Jun 11 where security-hardening and the service refactor had diverged (1233–1280, 14 files), resolved consistently toward the service-based, scope-threaded approach; a retrieval evaluation harness with metrics, a labeled corpus, and a weight-sweep runner (1333–1344); opt-in parser shared-secret auth (C2) shipped with tests probing empty tokens and duplicate-header bypass vectors (1416–1456); and a documentation pass — expanded CLAUDE.md plus per-connector guides (1459–1466). Jun 13 sees multiple PRs (#5 to recover orphaned review items) merged to main. Jun 14 closes with a full codebase self-survey, a fragility hunt that produces a hardening plan for search-index guards against silent drizzle-kit drops (1619, PR #7), and a multi-phase deployment plan that reaches into sibling repos — deciding cpa-backend is redundant with rag-system and the cpa-knowledge-base UI shell is worth lifting (1683–1694).
