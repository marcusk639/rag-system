# Week 5 (W37): Sep 07 - Sep 11, 2026 — The Night the Reviewer Reviewed Itself

_A twelve-hour all-nighter in which every instrument the project built to check its own work turned out to need checking._

## The Story

The week is really one shift. It starts at 12:17a on Sep 7 and runs unbroken to 12:09p — twelve hours, roughly forty session boundaries — then goes dark for four days and returns for a single Friday evening at 5:50p on Sep 11 to clean up what the all-nighter left on the floor.

The first hour is productive and unremarkable. The PORT trap from PR #56 gets closed properly: a fallback mechanism in core config with three-tier precedence (3527, 3530, 3907). A `renderManifest` function lands with "strict Teams manifest validation" and a 43-test suite behind it (3534, 3540). A package builder script. A TLS detection utility, `isPostgresTlsActive()`, extracted specifically so the thing could be tested (3607, 3613). PR #56 merges at 1:27a. Good mechanical work, all of it committed with confidence.

Then the shift's real subject arrives, and it is the same work coming back.

**The manifest validator.** At 4:36a a security review opens on code written four hours earlier and finds JSON injection via environment variables (3903). The existing test suite passes and does not see it (3909). Direct execution confirms it (3911), then escalates: SSO_SCOPE validation bypassed (3916), and GUID validation "completely bypassed" via `DEVELOPER_NAME` field injection (3919). Both CRITICAL. Both in the function whose selling point was strict validation.

**The TLS detector.** At 4:42a `isPostgresTlsActive()` is found bypassable by duplicate `sslmode` parameters — a false positive claiming encryption where there is none (3926). Three minutes later it is MULTIPLE failures: duplicate params, case sensitivity, regex-versus-parser disagreement (3932). The fix takes four attempts. `URL.searchParams` can't parse `postgres://` (3939). The answer is `getAll().at(-1)` — the driver reads the _last_ `sslmode`, not the first (3940). Eleven URL shapes, 100% driver parity (3958).

**The grounding harness.** `scripts/check-kb-grounding.mjs` exists to measure whether the deployed system answers from documents that exist. It reports 17 of 47 documents permanently blocked by the TRI guard (3850). Marcus, S818: show me one. The answer is a 1099 processing SOP caught on contextual pattern match (3869, 3870) — and then the harder finding, that the guard blocks 82% of documents with _no detectable patterns at all_ (3871). But the harness itself has four measurement defects: 429 backoff reading the wrong field, `documentExists` caching every non-200 as missing, a consumed 422 body, refusal matching so broad it scored real citations as guard blocks. The instrument was manufacturing its own alerts (3927, 3929).

**Prettier.** The CI quality gate is red. Claude establishes it was already red on main and not caused by the current change (3787, 4011) — then locates the cause at line 156 of `PILOT-LAUNCH-STATUS.md`: a markdown table nested inside a list item with a bold span across indented continuation lines, re-indenting itself forever (4019). A document the project wrote, in a format the project chose, that the project's own formatter cannot reach a fixed point on. Issue #62 filed; bisection-by-line-count documented as technique.

Marcus's register flattens into a metronome — S811, S858, S879, the same sentence three times: _continue with highest priority items to produce MVP ready for live use within TWK and Microsoft Teams._ Not a decision. A heading, repeated.

By Friday the arithmetic is grim and then fine: PR #61 merged before its critical fixes landed, stranding them on a dead branch (a second stranding, after 3842). PR #64 is opened to recover them. TRI policy set to `warn` takes answerability from 65% to 100% with refusal accuracy intact. Mutation testing confirms the new regression tests actually catch what they claim (3947).

## Where We Are

Two pull requests are queued and ordered: #64 first, because it carries the grounding fixes and the format-gate unblock, then #63, whose quality check should pass once #64 lands. Neither has merged. A stashed `token-log.md` is waiting to be popped, and the suggestion to untrack it — so session files stop colliding at merge — is a note, not a decision.

The TRI guard is running in `warn` mode, which is a mitigation wearing a fix's clothes. Answerability went 65% to 100% by asking the guard to stop enforcing, not by correcting the contextual matching that blocks 82% of documents against no detectable pattern. Issue #62 is open on the format gate; one file was fixed, the class of defect was not.

Older debts carry unchanged. Automated PITR restore is still broken on Railway volumes; recovery still needs a human, root, SSH, and a runbook. The permanent off-Railway backup destination is still blocked on admin consent, and the S3 stopgap is on record as not surviving account loss. `railway connect rag-postgres` has never been explained. `ingestion_jobs` and `ingest_log` still disagree with the schema. Parser metadata still crosses the boundary unvalidated.

The Teams bot's Docker build and health endpoint were validated on Sep 7; the bot itself is still waiting on an Azure subscription nobody has bought. The P0 content audit gate was prepared and not run.

Production is live, answering, and auto-deploying from main — which on Sep 7 sat 16 commits ahead of what was actually running. The week's lesson is the one the project keeps re-learning at increasing cost: the thing you built to tell you whether it works is also a thing you built.
