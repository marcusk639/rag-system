# Teams KB Bot (apps/teams-bot) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `apps/teams-bot`, a Microsoft Teams conversational bot that lets TWK staff ask the KB from a DM or a channel @mention and get an adaptive-card answer with citations and the server-sourced AI-draft disclaimer, preserving the exact per-user scoping and audit logging the existing surfaces enforce.

**Architecture:** The bot is another BFF (like `apps/web`): it authenticates the Teams user via Entra SSO → `oid`, computes a source-id scope set (DM = the asker's grants; channel = the intersection of all channel members' grants minus client-confidential), mints the same 60s `signInternalScopeToken`, and calls the existing RAG HTTP API `POST /ask` with that bearer token plus an `X-RAG-Channel: teams` header. The API is the single enforcement + audit point; the bot has no authz/retrieval logic.

**Tech Stack:** TypeScript, Bot Framework SDK (`botbuilder`), Express (matching `apps/mcp`), `@rag/core` (`signInternalScopeToken`), `@rag/db` (`resolveSourceIdsForUser`, new `resolveSharedSourceIdsForUsers`), the RAG HTTP API, Railway.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-07-16-teams-bot-design.md` — the source of truth; every task implements part of it.
- TypeScript only, new pnpm workspace app under `apps/`. No Python. Node `>=22`, `pnpm@9.12.0`; install deps with `pnpm add --filter @rag/teams-bot <pkg>` (or add to the app's package.json then `pnpm install`). Never edit `pnpm-lock.yaml` by hand.
- All DB access via `@rag/db` typed queries; never import `pg`/`drizzle-orm` directly.
- All backend calls go through the RAG HTTP API via a minted scope token; never a shared static token, never direct DB reads of chunks/embeddings.
- **Fail closed everywhere identity or scope can't be positively established** — no verified `oid` ⇒ no answer, never a fallback/admin scope (mirror `getScopeAssertionToken` and `apps/web/src/lib/auth.ts`).
- Edit `env.example`, never a real `.env` (hook-blocked). Commit format `<type>: <description>`, no attribution footers. A pre-commit hook (prettier + secret scan + 800-line guard) runs on every commit; never use `--no-verify`. A PostToolUse prettier hook may reformat after edits — expected.
- **The channel-scope isolation test (Task 5) is mandatory, not optional.**
- `resolveSharedSourceIdsForUsers` MUST reuse the same grant UNION as `resolveSourceIdsForUser` (the two `SELECT`s over `staff_client_assignments`→`source_client_assignments` and `staff_source_assignments`), so channel and DM scope can never diverge on what "a grant" means.
- The disclaimer is **server-sourced**: render `result.disclaimer` from the API response; never hard-code disclaimer text in the bot.
- Tests must not add this app to any Docker-dependent CI-blocking path beyond the existing e2e workflow; unit tests (Bot Framework `TestAdapter`, mocked `@rag/db`/fetch) carry the logic.

  ```typescript
  /**
   * Source-ids that EVERY user in `userIds` has an active grant to, excluding
   * client-confidential sources. Used to compute a channel-safe scope for the
   * Teams bot: a source appears only if all channel members can already see it,
   * so a channel answer can never expose content a member lacks access to.
   *
   * Reuses the SAME grant UNION as resolveSourceIdsForUser (client-routed +
   * direct grants) so channel scope and per-user scope never diverge on what a
   * grant is. Intersection = HAVING count(DISTINCT user_id) = number of members.
   * Empty `userIds` returns [] (no shared scope over an empty member set).
   */
  export async function resolveSharedSourceIdsForUsers(
    db: Db,
    userIds: string[],
  ): Promise<string[]> {
    const distinct = [...new Set(userIds)];
    if (distinct.length === 0) return [];
    const rows = await db.execute<{ source_id: string }>(sql`
      SELECT grants.source_id
      FROM (
        SELECT sta.user_id, sca.source_id
        FROM staff_client_assignments sta
        JOIN source_client_assignments sca ON sca.client_id = sta.client_id
        WHERE sta.user_id = ANY(${distinct})
          AND sta.revoked_at IS NULL
        UNION
        SELECT user_id, source_id
        FROM staff_source_assignments
        WHERE user_id = ANY(${distinct})
          AND revoked_at IS NULL
      ) grants
      JOIN sources ON sources.id = grants.source_id
      WHERE sources.data_class <> 'client_confidential'
      GROUP BY grants.source_id
      HAVING count(DISTINCT grants.user_id) = ${distinct.length}
    `);
    return rows.rows.map((r) => r.source_id);
  }
  ```

  Confirm `Db`, `sql`, and the `db.execute<T>` generic usage match `resolveSourceIdsForUser` immediately above it (same imports; no new import needed). Export from `packages/db/src/index.ts` next to `resolveSourceIdsForUser`.
